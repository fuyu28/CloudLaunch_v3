# settings-no-env

- 日時: 2026-11-27 00:38 (JST)

## 当初の要求 / 背景

`docs/adr/2026-11-18_22-15_settings-connection.md` は、R2 の接続情報を DB の設定と資格情報に置き、環境変数 `CLOUDLAUNCH_S3_*` が 1 つでもあれば、CLI と GUI のどちらも、すべてを環境変数から読むと決めた（「環境変数の優先」）。環境変数は、Linux と versitygw で開発するためのものだった（#140 の決めたこと 6）。設定を書く手段は GUI の設定画面だけで、CLI は読むだけだった（同じ ADR の「CLI」）。

#181 で GUI の設定画面ができ、Linux でも資格情報を `credential.json` に保存できるようになった。一方で、環境変数を残しているために、次のものが要っている。

- 設定画面の、環境変数が効いていることの案内（`EnvNotice`）
- 環境変数で足りない項目があることを表す `settings.ErrEnvIncomplete` と、その案内の文言（CLI と GUI の帯）
- 「設定画面で保存したのに使われない」という状態

仕様書（`docs/sync-spec.md`）3 章は、接続情報の置き場所を DB の設定と資格情報と決めており、環境変数には触れていない。

## 決定事項

### やめる環境変数の範囲

- 事項: どの環境変数をやめるか
- 決定内容: 接続情報の `CLOUDLAUNCH_S3_ENDPOINT`・`_REGION`・`_BUCKET`・`_ACCESS_KEY_ID`・`_SECRET_ACCESS_KEY` を、CLI と GUI のどちらでも読まない。CLI と GUI は、DB の設定と資格情報だけから読む。`settings` から、環境変数を読む `Config.Getenv`・`UsesEnv`・`ErrEnvIncomplete` を消す。契約テスト用の `CLOUDLAUNCH_TEST_S3_*`（`docs/adr/2026-10-23_01-53_objstore.md`）は残す
- 判断理由: 環境変数で渡す目的だった Linux での開発は、保存した設定で足りるようになった。接続情報の読み元が 1 つになれば、どこから読んだかの案内と、環境変数で足りないときの分類がいらなくなる。契約テストは、DB も資格情報もない状態で versitygw につなぐためのもので、アプリの設定ではないので残す

### CLI のコマンドの形

- 事項: CLI で設定をどう書き、どう見るか
- 決定内容: `config remote`・`config device-name`・`config show` を足す。どれも `--data-dir` を受け付ける。項目ごとに書く `config set <key> <value>` の形にはしない
- 判断理由: 環境変数をやめると、CLI だけで接続先を入れる手段がなくなる。接続情報は、全部を揃えて検証してから一度に保存する（`settings.SaveRemote`。シークレットを変えずにアクセスキー ID だけを変えるのは拒否する）ので、項目を 1 つずつ書く形は合わない。settings の公開 API（`SaveRemote`・`SaveDeviceName`・`SavedRemote`）に 1 対 1 で合わせる

### 値の入れ方

- 事項: `config remote` と `config device-name` で、値をどう受け取るか
- 決定内容: フラグでは受け取らず、すべてを端末で対話して尋ねる。各項目に保存した値を `[ ]` で出し、Enter だけなら今の値を残す。シークレットは、入力を伏せて尋ね（`golang.org/x/term`）、保存してあれば `[保存済み]` とだけ出す。全部を尋ね終えてから、`SaveRemote` でまとめて検証して保存する。標準入力が端末でなければ、何も尋ねずに拒否する
- 判断理由: シークレットをフラグで渡すと、シェルの履歴やプロセスの一覧に残る。シークレットだけを別の渡し方にすると、ほかの項目と入れ方が分かれる。全部を対話にすれば、入れ方が 1 つになり、GUI の設定画面（保存した値を入力欄に入れておき、シークレットだけは空なら今の値を残す）と同じ規則になる。省いた項目を何で補ったかが画面に出るので、補っても、どの値を保存したかが分かる。スクリプトからは実行できなくなるが、CLI は同期コアを確かめる道具で（AGENTS.md の「構成」）、設定は接続先ごとに一度入れるだけなので困らない。パイプで何行も流す入力は、項目の順番を取り違えやすいので受け付けない。`golang.org/x/term` は、すでに間接の依存として入っている

### 何も変えなかったとき

- 事項: すべての項目で Enter だけを押したときに、保存するか
- 決定内容: 保存せず、変えなかったことを出す。`config device-name` で、deviceName を保存しておらずホスト名を出したときも同じにする
- 判断理由: deviceName は、保存するまで DB に書かず、読むたびにホスト名を返す（`docs/adr/2026-11-18_22-15_settings-connection.md` の「deviceName の保存と検証」）。Enter だけで保存すると、そのときのホスト名が書かれ、ホスト名を変えても古い名前が残る。接続情報も同じ扱いにして、2 つのコマンドの振る舞いを揃える

### 保存した値の表示

- 事項: どの接続先を使っているかを、CLI でどう確かめるか
- 決定内容: `config show` で、保存した接続情報（エンドポイント・Region・バケット・アクセスキー ID）と deviceName を出す。シークレットは、保存してあるかどうかだけを出す。接続情報を保存していなければ、未設定であることを出す
- 判断理由: 環境変数をやめると、接続先は DB の設定と資格情報にしか現れず、CLI で確かめる手段が要る。GUI の設定画面と同じく `SavedRemote` を使い、シークレットを画面に出さない（同じ ADR の「シークレットの表示」）

### 環境変数が残っているとき

- 事項: `.env` などに `CLOUDLAUNCH_S3_*` が残っているときの扱い
- 決定内容: 黙って無視し、警告を出さない。`.env.example` から `CLOUDLAUNCH_S3_*` を消す
- 判断理由: 環境変数を使っていたのは開発の手元だけである。残った環境変数で困るのは、環境変数で versitygw に向けて記録した base が DB にあり、同じ置き場所に R2 を保存してあるときで、CLI が警告なしに R2 へつなぎ、versitygw の base を前提に転送する。この状態は、環境変数を使っていた手元の DB にしかなく、新しく作られることはないので、`.env` から `CLOUDLAUNCH_S3_*` を消し、versitygw を相手にした記録のある置き場所を使わないことで防ぐ。警告を出すと、一度きりの移行のためのコードが残り続ける

### ほかのプロセスとの関係

- 事項: CLI で設定を書くときに、PC 全体の同期ロックを取るか
- 決定内容: 取らない。GUI が動いている間に CLI で保存したときは、GUI が新しい値を使い始めるのは、再起動するか、GUI の設定画面で保存したときになる
- 判断理由: 同期は、始めるときに組み立てたコアを最後まで使い、途中で設定を読み直さない（`docs/adr/2026-11-18_22-15_settings-connection.md` の「GUI で保存した後の反映」）。走っている同期の途中で設定を書いても、その同期の接続先は変わらない

### 開発での接続先

- 事項: 開発で、アプリ（CLI と GUI）をどの接続先につなぐか
- 決定内容: アプリは R2 だけにつなぐ。versitygw は objstore の契約テストだけで使い、アプリの接続先にはしない。AGENTS.md の「開発環境」に、接続先の切り替えの手順は書かない
- 判断理由: versitygw でアプリを動かしていたのは M1〜M2 で CLI を確かめるためで、今は CLI の振る舞いを変えた PR は R2 で確かめる（AGENTS.md の「AI エージェントの作業」）。接続先を切り替えると、同じ DB のまま base とリモートの対応が混ざる。`--data-dir` で置き場所を分けても、Windows の資格情報は資格情報マネージャーの `CloudLaunch/R2` の 1 件で、置き場所によらず共通なので、別の置き場所に入れたキーが既定の置き場所のキーを上書きする。資格情報を置き場所ごとに分けるには platform の変更と既存の資格情報の移し替えが要り、切り替える必要がなくなった今は見合わない。複数の PC を真似るために `--data-dir` を分ける使い方は、同じ R2 を見るので、資格情報を共有しても困らない

### 置き場所

- 事項: CLI の `config` のコードをどこに置くか
- 決定内容: `cmd/cloudlaunch-cli/config.go` に置き、テストは書かない。値の検証と保存は `internal/settings` が行い、CLI は尋ねる・出すだけにする
- 判断理由: CLI の配線にはテストを書かない（AGENTS.md の「テスト」）。Enter だけで今の値を残す処理は、入力と保存した値を比べるだけで、検証の規則を持たない。`main.go` は 1,000 行を超えているので、コマンドの群ごとにファイルを分ける

### PR の分け方

- 事項: PR をどう切るか
- 決定内容: 1 つにする。settings から環境変数を消すこと、CLI の `config`、GUI の環境変数まわりの削除、`.env.example` と AGENTS.md の更新を含める
- 判断理由: 環境変数を消すと、CLI で接続先を入れる手段は `config remote` しかなくなるので、分けると間の状態で CLI が R2 につなげない。見込みは本番のコード 150 行、テスト 150 行ほどで、オーナーが全行を読める量に収まる
