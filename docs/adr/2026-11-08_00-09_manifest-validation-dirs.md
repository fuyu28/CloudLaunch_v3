# manifest-validation-dirs

- 日時: 2026-11-08 00:09 (JST)

## 当初の要求 / 背景

2026-11-07_23-41_manifest-validation.md で実装した 6 章「不正な manifest」の規則には、当たる manifest が HEAD になると、どの PC も Pull できなくなる穴が 2 つ残っていた。

- 6-M5 が path 全体だけを比べるので、ディレクトリの部分だけが大文字小文字で違う path（`dir/a.sav` と `DIR/b.sav`）を拒否しない。また、同じ名前をファイルとディレクトリの両方に使う path（`a` と `a/b.sav`）を拒否しない
- 6-M10 が、予約名の後ろの空白（`aux .sav`）を取り除かずに比べる

仕様書の変更（#77）で、6-M5 をディレクトリの部分に広げ、6-M10 で末尾の空白を取り除き、ファイルとディレクトリの衝突を 6-M13 として足すと決めた。大文字への揃え方は、Unicode の単純な大文字への対応のままとした。この ADR は、その実装の決定を記録する。

## 仕様

- 6-M5 と 6-M13 の検査の仕方
- 6-M10 の空白
- テスト

## 決定事項

### 6-M5 と 6-M13 の検査の仕方

- 事項: path とそのディレクトリの部分の重複と衝突を、どう検査するか
- 決定内容: `validatePaths` で、大文字に揃えた名前から「元の綴り」と「ディレクトリかどうか」への map を 1 つ持つ。各 path について、ディレクトリの部分を短い順に、最後に path 全体を、次の規則で map と照らしてから登録する
  - 揃えた名前が map になければ登録する
  - あって、ディレクトリかどうかが違えば 6-M13 とする
  - あって、どちらもディレクトリで、綴りが違えば 6-M5 とする
  - あって、どちらもファイルなら 6-M5 とする（綴りが同じ重複も含む。Pull では 6-M9 が先に拒否する）
  - 大文字に揃えるのは要素ごとに 1 回とし、揃えた要素を継ぎ足して接頭辞の名前を作る。エラーには、衝突した名前に加えて、それを登録した path を 2 つとも出す
- 判断理由: ファイルとディレクトリを 1 つの map で扱えば、path の並び順によらず（`a` が `a/b.sav` より先でも後でも）衝突を見つけられる。接頭辞ごとに揃え直すと、手間が path の深さ×長さになる。要素ごとに揃えて継ぎ足せば、path の長さに比例する。ディレクトリの部分だけを出すと、大きなセーブフォルダでどのファイルを直せばよいか分からないので、元の path も出す。仕様書 2 章は 6-M13 を local の検証に含めないが、関数は分けない。local で 6-M13 に当たるのは、大文字小文字を区別するフォルダの `a` と `A/b.sav` のように綴りが違う組み合わせだけで、それは 6-M5 にも当たる。そのため、分けても拒否するかどうかは変わらず、違うのはエラーの文言だけである

### 6-M10 の空白

- 事項: 末尾の空白をどこで取り除くか
- 決定内容: 要素の最初の `.` より前の部分から、末尾の半角空白（U+0020）だけを `strings.TrimRight` で取り除いてから、予約名と比べる
- 判断理由: 仕様書は末尾の空白だけを取り除くと決めている。先頭の空白はデバイス名として扱われないので取り除かない

### テスト

- 事項: どの OS で何を確かめるか
- 決定内容: Pull の 6-M5・6-M10・6-M13 は、偽のリモートに manifest を置いて、どの OS でも確かめる。manifest は 6-M9 を通るよう path の昇順に並べる。local の、ディレクトリの部分の大文字小文字の重複は、Windows では作れないので `t.Skip` で飛ばし、Linux で確かめる
- 判断理由: Pull の検証は 6-M9 を 6-M5・6-M13 より先に行うので、並びが崩れていると 6-M9 で拒否され、確かめたい規則に届かない

## 結果 / 影響

- 決定事項のとおりに実装した。差分は本番が約 50 行、テストが約 60 行で、見込み（150 行前後）より小さかった
- R2 で次を確かめた。`dir/a.sav` と `DIR/b.sav` を持つセーブフォルダは Status で止まる。`a` と `a/b.sav` を持つ manifest（6-M13）と、`aux .sav` を持つ manifest（6-M10）を HEAD にした世代は、Pull が何も変えずに止まる
- 6-M13 の深い階層（`a/B/c.sav` と `a/b`）、名前の先頭が同じだけで正当な組み合わせ（`a` と `ab/c.sav`、`x.sav` と `x/b.sav`）、6-M10 の空白の扱い（`aux   .sav` は拒否し、` aux.sav` は通す）もテストで固定した。`/` の区切りでなく文字列の先頭で比べる変更や、先頭の空白も取り除く変更を検出するため
- 仕様書 6-M13 の「local のファイルシステムでは起きない」は、大文字小文字を区別するフォルダでは成り立たない。ただし、そこで起きる組み合わせは 6-M5 にも当たり、仕様書どおり拒否されるので、仕様書は直していない
