# git-hooks-lefthook

- 日時: 2026-10-23 00:30 (JST)

## 当初の要求 / 背景

コミットの前にフォーマッタとリンタを適用したい。CloudLaunch_Go では「タスクの終わりに `./scripts/run-all-lint-format.sh` を実行する」というルールだけがあり、実行を忘れても何も止まらなかった。

git フックは `--no-verify` で飛ばせるので、ルールを最終的に守らせるのは CI である。フックの役割は、CI で落ちる前に手元で気づけるようにすることである。v3 は Go で書き、GUI の段階でフロントエンドの道具が加わる見込みがある（フロントエンドの第一候補は Go のテンプレート + htmx、次点は Svelte）。

## 仕様

- フックを管理する道具
- フックで何を実行するか

## 決定事項

### フックを管理する道具

- 事項: git フックの管理方法
- 決定内容: lefthook を使い、バージョンは mise で固定する
- 判断理由: lefthook は Go 製の単体のバイナリで、Go のプロジェクトに別の実行環境を持ち込まない。ステージしたファイルへの絞り込み、直したファイルの再ステージ（`stage_fixed`）、並列実行を設定だけで書け、Windows でも同じように動く。pre-commit は Python を、husky + lint-staged は Node とルートの `package.json` を要する。`core.hooksPath` に自作のスクリプトを置く方法は依存がないが、再ステージなどを自分で書く必要があり、フロントエンドの道具を足すときに書き直しになる

### フックで実行すること

- 事項: pre-commit フックの中身
- 決定内容: ステージした `.go` ファイルにフォーマッタ（gofmt・goimports）をかけて再ステージする。リンタ（golangci-lint）はモジュール全体に `GOOS=windows` と `GOOS=linux` の両方でかける。テストはフックで実行せず、CI に任せる
- 判断理由: golangci-lint はパッケージ単位で解析するので、ステージしたファイルだけをリントすることは正確にはできない。golangci-lint は実行している OS 向けのファイルしか解析しないため、Linux で開発しながら本番の Windows 向けのコードを検査するには `GOOS=windows` が要る。テストは時間がかかり、コミットのたびに待つ負担が大きい

## 結果 / 影響

- フォーマットの崩れとリントの違反は、コミットの時点で気づける
- clone したあとに `mise install` と `lefthook install` を実行する手間が増える
- golangci-lint の `run` はフォーマットの差分を報告しないため、CI では別に `golangci-lint fmt --diff` で確かめる
